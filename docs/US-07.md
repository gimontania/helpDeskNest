# US-07 · Listar usuarios por rol

## Reglas de acceso

El rol es un campo directo del usuario: ADMIN, AGENTE o EMPLEADO. No existen tablas de permisos.

| Operación      | ADMIN     | AGENTE    | EMPLEADO | Sin JWT |
| -------------- | --------- | --------- | -------- | ------- |
| GET /usuarios  | Permitido | Permitido | 403      | 401     |
| POST /usuarios | Permitido | 403       | 403      | 401     |

Solo ADMIN puede crear cuentas ADMIN o AGENTE mediante POST /usuarios. El registro público POST /auth/register siempre crea EMPLEADO, incluso si el cliente intenta enviar un rol interno. El primer administrador requiere aprovisionamiento por una persona responsable de la base; prisma/seed.ts contiene cuentas únicamente para desarrollo y demostración.

## Listado y filtro

Enviar Authorization: Bearer <JWT> obtenido en POST /auth/login.

- GET /usuarios: lista todos los usuarios ordenados por nombre.
- GET /usuarios?rol=AGENTE: lista los agentes.
- Los otros valores válidos son ADMIN y EMPLEADO, en mayúsculas.
- Un filtro inválido devuelve 400; sin coincidencias devuelve [].
- Cada usuario expone únicamente id, nombre, email, rol y creadoEn.
- Nunca se seleccionan password ni passwordHash en la consulta del listado.

Ejemplo de respuesta:

```json
[
  {
    "id": "b55667f0-80bf-465a-a957-72403fc5f911",
    "nombre": "Agente Prueba",
    "email": "agente@helpdesk.test",
    "rol": "AGENTE",
    "creadoEn": "2026-10-06T00:00:00.000Z"
  }
]
```

## Arquitectura del curso

UsuariosModule mantiene su Controller y Service. El Controller usa JwtAuthGuard y RolesGuard; ListarUsuariosDto valida el enum mediante class-validator. UsuariosService consulta PostgreSQL a través de Prisma usando una selección explícita de campos públicos. Se aprovecha la implementación presente en main, sin duplicar rutas.

## Verificación

```bash
pnpm install --frozen-lockfile
pnpm exec prisma generate --config prisma7.config.ts
pnpm test -- --runInBand src/usuarios src/auth/auth.service.spec.ts
pnpm build
```

Las pruebas HTTP utilizan JWT firmado y estrategia Passport reales con el servicio de usuarios simulado, sin conexión a PostgreSQL. Las pruebas del servicio verifican el filtro y la selección enviada a Prisma. Para la demo con base real, configurar DATABASE_URL y JWT_SECRET, aplicar migraciones y usar las cuentas de desarrollo del seed. No ejecutar el seed de demostración en producción.
