# US-15 · Comentar en un ticket

POST /tareas/:tareaId/comentarios requiere JWT y un UUID válido:

```json
{ "contenido": "El equipo sigue sin encender." }
```

Devuelve 201 con id, tareaId, contenido, creadoEn y autor (id, nombre, rol). Nunca incluye contraseña ni hash del autor.

## Reglas

- EMPLEADO solo puede comentar en sus propios tickets.
- ADMIN y AGENTE pueden comentar cualquier ticket, según la visibilidad vigente del módulo Tareas.
- El autor se obtiene exclusivamente del JWT; la fecha la genera PostgreSQL con el valor por defecto de Prisma.
- Los campos adicionales enviados por el cliente, incluidos autorId, autor y creadoEn, se ignoran mediante whitelist del ValidationPipe. El servicio también construye explícitamente los datos, sin copiar esos campos.
- El contenido debe ser texto no vacío; se recortan espacios al principio y al final.
- Esta historia no restringe comentarios por estado del ticket.

## Errores

| HTTP | Motivo                                                        |
| ---- | ------------------------------------------------------------- |
| 400  | UUID inválido o contenido ausente, vacío o de tipo incorrecto |
| 401  | JWT ausente, inválido o vencido                               |
| 404  | Ticket inexistente o ticket ajeno a un EMPLEADO               |

El 404 para tickets ajenos conserva la política actual de Tareas y evita revelar su existencia. No se guarda un comentario si el ticket no es visible.

## Arquitectura y demo

ComentariosModule conserva Controller y Service propios. CrearComentarioDto usa class-validator/class-transformer. JwtAuthGuard autentica y TareasService aplica la visibilidad. Prisma registra autorId y creadoEn; no se necesita migración adicional.

Para demostrar: crear ticket con JWT de EMPLEADO, comentar y consultar GET /tareas/:tareaId/comentarios. Enviar autorId y creadoEn falsificados y verificar que el autor sigue siendo el usuario autenticado y que la fecha corresponde al momento de creación. Intentar comentar con otro empleado: 404. Probar AGENTE en ticket existente: 201 y ticket inexistente: 404.

```bash
pnpm exec prisma generate --config prisma7.config.ts
pnpm test -- --runInBand src/comentarios
pnpm build
```

Las pruebas HTTP usan JWT y validación reales con el servicio simulado. Las pruebas del servicio de comentarios usan TareasService real y Prisma simulado para verificar la regla de propiedad. La fecha por defecto está definida en el esquema existente; la demo con PostgreSQL real permite comprobarla de extremo a extremo.
